## How the workshop works

Every act has the same shape. A short talk on one idea. A hands-on step where you add that one idea to the app you are building. A look at what changed, so you can see the improvement before moving on.

You start in a sandboxed copy of your own harness with no skills, no plugins and no MCP servers, so everyone begins from the same place. You give it one loose prompt and get a wildly different app from the person next to you. Then, act by act, you add the pieces that turn a prompt into a factory.

<CardGrid stagger>
	<Card title="Day 1: from prompt to pipeline" icon="rocket">
		The sandbox and the vibe. Guardrails. Gates. Specifications. By the end of the day one agent builds one feature at a time, the way you want it built, and cannot commit work that fails the checks.
	</Card>
	<Card title="Day 2: from pipeline to factory" icon="setting">
		Tickets. Isolation. Proof. Review. The orchestrator. Unattended runs. By the end of the day an orchestrator dispatches subagents per ticket, verifies each one, has each pull request reviewed on a different model, and loops until the board is empty. A small loop with guards can restart it without you at the keyboard. Every act ends with what it cost, so you see the cost fall as the strongest model judges and cheaper ones do the work.
	</Card>
	<Card title="Harness and model agnostic" icon="puzzle">
		The worked path uses Claude Code. Every harness-specific step has tabs for Codex CLI, Gemini CLI and Cursor. The ideas do not depend on any of them.
	</Card>
	<Card title="Proven before it was written" icon="approve-check">
		Every Claude Code step in this guide was run, in order, on the demo app before it was written down. The Codex CLI tabs were then tested with Codex CLI 0.160.0 through OpenRouter, and the Cursor tabs with Cursor CLI 2026.10.01 on a Free plan (no named models). The Gemini CLI tabs were tested headless with Gemini CLI 0.62.0 on a free API key (personal Google sign-in no longer works, so use an API key). Interactive-only steps are marked as not run. The act 10 loop was only tested against a stand-in harness. The demo repository has a git tag per act so you can catch up at any point.
