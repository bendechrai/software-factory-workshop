Do this the day before. It takes about twenty minutes, most of it waiting on downloads. Everything here is checked with one command at the end.

## What you need

<Steps>

1. **A coding harness you already use.** Claude Code is the worked path in this guide. Codex CLI, Gemini CLI and Cursor are covered in tabs wherever a step differs. You need a signed-in account for whichever one you bring.

   <Tabs syncKey="harness">
     <TabItem label="Claude Code">
       ```bash
       curl -fsSL https://claude.ai/install.sh | bash
       claude --version
       ```
       Any build from 2.1.277 onwards. That is the version that reads `AGENTS.md` natively, which the workshop relies on.
     </TabItem>
     <TabItem label="Codex CLI">
       ```bash
       npm install -g @openai/codex
       codex --version
       ```
       Written from the docs, not run.
     </TabItem>
     <TabItem label="Gemini CLI">
       ```bash
       npm install -g @google/gemini-cli
       gemini --version
       ```
       Use npm, not Homebrew. The Homebrew formula was several releases behind when this was written.

       Do not plan on "Login with Google" with a personal account. On 2026-10-02 it failed with: "Failed to sign in. Message: This client is no longer supported for Gemini Code Assist for individuals. To continue using Gemini, please migrate to the Antigravity suite of products: https://antigravity.google". Google stopped serving Gemini CLI to Gemini Code Assist for individuals, Google AI Pro and Google AI Ultra accounts on 2026-06-18. Use a Gemini API key from https://aistudio.google.com/app/apikey instead: `export GEMINI_API_KEY="<your key>"`, start `gemini` and pick "Use Gemini API key". Vertex AI and Gemini Code Assist Standard or Enterprise licences are documented as still supported. The install command itself was not run (the tests used npx), and the sign-in failure was observed.

       Tested with Gemini CLI 0.62.0 (via npx, free AI Studio key, 2026-10-02): the API key route works headless. A free key allows about 20 requests a day PER MODEL (observed), not 250. `gemini-3.1-pro` has no free quota, and `gemini-2.5-pro` is closed to new keys (404). These models worked: `gemini-2.5-flash`, `gemini-3-flash-preview`, `gemini-3.1-flash-lite-preview` and `gemini-flash-latest`. Frequent 503 "high demand" errors are retried by the CLI. Each agent turn is several requests, so for two workshop days a paid key is realistic.

       Two traps. A failed Google sign-in leaves `security.auth.selectedType` set to `oauth-personal` in settings, and then headless runs fail even with the key set: remove that setting or set it to `gemini-api-key`. And in a new folder, headless runs stop with "not running in a trusted directory" unless you set `GEMINI_CLI_TRUST_WORKSPACE=true`, pass `--skip-trust`, or trust the folder once in an interactive session.
     </TabItem>
     <TabItem label="Cursor">
       ```bash
       curl https://cursor.com/install -fsS | bash
       agent --version
       ```
      The command-line agent is called `agent`. The workshop uses it rather than the editor, so that every step is a command you can copy.
      Tested with Cursor CLI 2026.10.01: `agent --version` works. The install command itself was not run, because Cursor was already installed.
     </TabItem>
   </Tabs>

2. **Node.js 24 or later.** The demo app runs TypeScript directly with Node's built-in type stripping and stores data with Node's built-in SQLite, so there is nothing to compile and no native modules.

   ```bash
   node --version
   ```

3. **git, and the GitHub CLI signed in.** Day two uses pull requests, and the ticket board closes tickets by asking GitHub whether the pull request merged.

   ```bash
   git --version
   gh auth status
   ```

4. **gitleaks**, which the commit gate uses to stop a secret reaching the repository.

   ```bash
   brew install gitleaks        # macOS
   # Linux: download a release from https://github.com/gitleaks/gitleaks/releases
   gitleaks version
   ```

5. **A browser for Playwright.** The push gate and the evidence step drive the app in a real browser. Installing the browser once now saves a long download during the workshop.

   ```bash
   npx -y playwright@latest install chromium
   ```

   <Aside type="caution">
   The Chromium download is about 360 MB. It took over 30 minutes on a slow connection while this guide was being written, so install it the day before.
   </Aside>

6. **OpenSpec and agentboard.** OpenSpec is installed globally, because the skills it writes into your project call a bare `openspec` command. agentboard is installed globally from npm too, and needs Node 22.16 or later. Its docs are at https://bendechrai.github.io/agentboard/ and the package is at https://www.npmjs.com/package/@bendechrai/agentboard.

   ```bash
   npm install -g @fission-ai/openspec@latest
   openspec --version
   npm install -g @bendechrai/agentboard
   agentboard version
   ```

   <Aside type="note">
   OpenSpec sends anonymous telemetry by default. Turn it off with `export OPENSPEC_TELEMETRY=0`.
   </Aside>

</Steps>

## Make the sandbox

Act 1 starts every attendee from the same place: your own harness, with none of the skills, plugins, MCP servers and memory you have gathered. You do not lose any of that. You point the harness at a fresh configuration directory for the two days and go back to your normal one afterwards.

<Tabs syncKey="harness">
  <TabItem label="Claude Code">
    ```bash
    mkdir -p ~/.claude-workshop
    alias claude-workshop='CLAUDE_CONFIG_DIR=~/.claude-workshop claude'
    claude-workshop auth login
    claude-workshop auth status
    ```
    `CLAUDE_CONFIG_DIR` moves everything that normally lives in `~/.claude`, including your login, so the first run asks you to sign in again. The status command should print `"loggedIn": true` and a `configDirectory` ending in `.claude-workshop`.

    Project files in a repository (`AGENTS.md`, `.claude/`, `.mcp.json`) still load. Only your home directory configuration is swapped out, which is exactly what you want.
  </TabItem>
  <TabItem label="Codex CLI">
    ```bash
    mkdir -p ~/.codex-workshop
    alias codex-workshop='CODEX_HOME=~/.codex-workshop codex'
    codex-workshop login
    ```
    The directory must exist before Codex starts; it does not create it. Your login lives inside `CODEX_HOME`, so sign in again. One thing does not move: personal skills in `~/.agents/skills` still load. If you have any, rename that folder for the two days. That advice applies to `~/.agents/skills` only: Codex's own bundled skills (such as `imagegen` and `skill-creator`) always load.

    If you route Codex through OpenRouter, the `OPENROUTER_API_KEY` environment variable plus `model_provider = "openrouter"` in `$CODEX_HOME/config.toml` replaces `codex login`. In that setup `codex login status` still says you are not logged in, even though runs work.

    Tested with Codex CLI 0.160.0 through OpenRouter.
     </TabItem>
  <TabItem label="Gemini CLI">
    ```bash
    mkdir -p ~/gemini-workshop
    alias gemini-workshop='GEMINI_CLI_HOME=~/gemini-workshop gemini'
    gemini-workshop
    ```
    `GEMINI_CLI_HOME` is the parent of the `.gemini` folder, not the folder itself. The first run creates `~/gemini-workshop/.gemini`. That part was run and works: it created `google_accounts.json`, `history` and `installation_id` there.

    Signing in with a personal Google account does not work (see the install tab for the error). Export your API key before starting instead:
    ```bash
    export GEMINI_API_KEY="<your key from Google AI Studio>"
    gemini-workshop
    ```
    Choose "Use Gemini API key" when asked. Tested with Gemini CLI 0.62.0: with `GEMINI_CLI_HOME` set, the real `~/.gemini` was untouched and all writes went to the sandbox folder. The key itself was not stored there. If a failed sign-in left `security.auth.selectedType` as `oauth-personal` in `~/gemini-workshop/.gemini/settings.json`, remove it or set it to `gemini-api-key`. The menu choice itself is interactive and was not run.
     </TabItem>
  <TabItem label="Cursor">
    ```bash
    mkdir -p ~/.cursor-workshop
    alias agent-workshop='CURSOR_CONFIG_DIR=~/.cursor-workshop agent'
    agent-workshop
    ```
    `CURSOR_CONFIG_DIR` moves only the CLI config, the sign-in record and your chats. It does NOT isolate MCP servers (`~/.cursor/mcp.json`), hooks (`~/.cursor/hooks.json`), skills (`~/.cursor/skills`, `~/.claude/skills`) or transcripts (`~/.cursor/projects`). Run `agent-workshop login` first, then `agent-workshop mcp list`. You will probably still see your servers, so disable each one for the two days with `agent mcp disable <name>` (tested: the status becomes `disabled`). Be aware that your global hooks still run.

    `--model <id>` is saved as the default, so a typo sticks until you pass another model. Named models need a paid Cursor plan. The Free plan allows only `auto` and has a usage limit (about 25 short headless runs exhausted it).

    Tested with Cursor CLI 2026.10.01 (sandbox behaviour, on a Free plan).
     </TabItem>
</Tabs>

Put the alias in your shell profile so it survives a new terminal. Everywhere this guide says "start your harness", it means this alias.

## Check everything at once

Make one folder for the whole workshop, clone the workshop repository into it, and run the check script from there. It prints one line per tool. Your `hop` app goes in the same folder in act 1, next to the clone.

```bash
mkdir -p ~/workshop && cd ~/workshop
git clone https://github.com/bendechrai/software-factory-workshop.git
software-factory-workshop/bin/check-setup.sh
```

If every line says `ok`, you are ready.
