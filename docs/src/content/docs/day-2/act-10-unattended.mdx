**The idea.** The factory runs without you at the keyboard. A small loop restarts the orchestrator in a fresh session each time. Each session has fresh context, and the state lives on disk: the board, the specs and git. A set of guards decides when the loop stops. You come back to merged PRs, a drained board, a log and a cost.

**Time:** about 60 minutes.

## The talk

1. **The Ralph loop.** Geoffrey Huntley's idea, at [ghuntley.com/ralph](https://ghuntley.com/ralph/), is very small: give an agent the same prompt, again and again, with fresh context each time, and keep the state in files. Our loop is that, with guards. Each iteration starts a new headless session with `.agents/loop/prompt.md`. There is no `--continue` and no `--resume`. The agent re-reads the board and the repo, does one change, and ends.

2. **Why fresh sessions beat one long one.** A long session fills up with old attempts, dead ends and stale facts. It gets slower and worse. This is context rot. A fresh session reads only what is true now. Anything that must survive goes where the next session will find it: a ticket comment, a spec, a commit.

3. **Four failure modes, and the guard for each.**

   | Failure mode | What happens | The guard |
   |---|---|---|
   | Runaway cost | The loop never ends, or one run spends without limit | An iteration cap, a time cap and a per-run budget |
   | Thrashing | The agent retries a ticket it cannot do | The same ticket blocked twice in a row exits with code 1, for a human |
   | Context rot | A long session gets worse as it fills | A fresh session each iteration |
   | Silent wrong work | Green checks, wrong result | The gates, the evidence and the reviewer from the earlier acts |

   The last one is why this act comes last. No guard in the loop can tell whether the work is right. The orchestrate skill does that: it checks every report itself and has every PR reviewed on a different model. The push hook runs the full preflight. The loop never merges around those gates and never uses `--no-verify`. If you skipped those acts, do not run this loop.

4. **The stop file.** `touch .agents/loop/STOP` ends the loop before the next iteration. You do not have to find the process. The run in progress finishes first. Remove the file before the next run, or the loop exits at once.

5. **The two-tier rule.** This comes from the author's holodeck project. Never make the factory the only way to change the factory. The loop, the skill and the board are the fast path. The manual path must keep working beside them. A person can edit, run `npm run verify`, commit and push with no agent and no loop. So the loop changes product code through tickets and PRs, and changes to the loop itself are made by a person.

6. **Cost.** An unattended loop is where cost gets away from you. Claude Code has a per-run budget flag, `--max-budget-usd`, and the default command uses it with a budget of $5 a run. The other harnesses have no such flag in this loop, so the iteration and time caps are your only control: keep `MAX_ITERATIONS` small. The Claude ledger reads Claude Code logs only. It cannot see Codex or OpenRouter spend. With Claude Code, the loop prints the ledger command for its own time window, and you run it. With any other harness and `OPENROUTER_API_KEY` set, the loop prints the OpenRouter spend of this loop itself, worked out from the usage lines it writes to `loop.log`.

### Running the loop with another vendor's harness

The loop is harness agnostic: it runs one command with the prompt as the last argument and reads the exit code. To prove that outside the harness this guide was built in, Codex CLI was run through OpenRouter. See the Codex tab for the setup, and "What you see" for the real run.

If macOS shows a security warning when Codex first runs, the package was checked. Every executable in the npm package is signed by OpenAI's Developer ID (team 2DC432GLL2), has the hardened runtime and no quarantine flag, and the system log showed no malware detection. If macOS says it cannot check the app, use System Settings, Privacy and Security, Open Anyway, or install it once with `brew install --cask codex` or `npm install -g @openai/codex`. If it says the app will damage your computer, do not override it.

**Set a spending limit.** With Codex, the loop has no per-run budget flag (Claude Code has `--max-budget-usd`). The OpenRouter key's spending limit is the real ceiling, so set one before you run the loop unattended.

### What this teaches

An unattended run is only as good as what verifies it afterwards. Here a separate verifier, on a different model, found what the loop's own reviewers missed. That is why act 10 comes after acts 7 and 8: the loop only runs the gates, it does not replace them. It is also why the first real run of anything gets a strict check before anyone presents it as proof. This run was good, and the page says where it was not.

### The guards and the exit codes

| Exit | Meaning | Causes |
|---|---|---|
| 0 | Normal end | The board is empty, the stop file exists, the iteration limit was reached, or the time limit was reached |
| 1 | A human is needed | The same ticket was blocked after two iterations in a row |
| 2 | Something is broken | `MAX_FAILURES` harness runs failed in a row (default 3), or bad usage |

"Board empty" means nothing is in todo, tests, implementing or review. Blocked tickets alone count as empty. A single failed run is logged and the loop goes on. The blocked check compares the blocked tickets after the last two iterations, so it can fire before iteration 3 at the earliest. The defaults are 5 iterations, 120 minutes and a 30 second cool-down.

### What the loop writes

- `.agents/loop/runs/<timestamp>-i<n>.json` holds the harness output of each run, with `.err` beside it for stderr.
- `.agents/loop/runs/<timestamp>-i<n>-sessions/` holds a copy of the harness's own session files from that iteration. For Codex these are the rollouts, which are the only record of each subagent and its model.
- `.agents/loop/loop.log` has one line per iteration: the iteration number, the start and end times, the exit code, and the open tickets before and after. With `OPENROUTER_API_KEY` set, it also has a line with `usage` and `limit_remaining` before and after each iteration. The key itself is never logged. This is the cost record for a Codex run.
- When the loop ends it prints the cost hint. If `HARNESS_CMD` starts with `claude`, it points at the Claude ledger. For any other harness, such as Codex, it prints the OpenRouter spend from this loop's usage lines, or says the cost is not visible to the ledger when there are none. For Claude Code the hint looks like this:

  ```text
  [factory-loop] cost of this loop (run from the repo; put CLAUDE_CONFIG_DIR=~/.claude-workshop in front if you use the sandbox):
  [factory-loop]   cd <your repo>
  [factory-loop]   node "<workshop>/tools/ledger/ledger.mjs" --since <loop start> --by agent
  ```

  For Codex with `OPENROUTER_API_KEY` set:

  ```text
  [factory-loop] OpenRouter spend of this loop: first usage $2.25, last usage $5.25, difference $3.0000
  ```

`runs/`, `STOP`, `loop.log`, `.ledger-cache.json` and `.agents/review/briefs/` are gitignored.
